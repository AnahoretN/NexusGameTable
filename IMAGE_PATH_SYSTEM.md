# Система путей изображений (Image Path System)

## Обзор

Новая компактная система предотвращает ошибки `RangeError` и `QuotaExceededError` при сохранении игр с большим количеством изображений. Вместо сохранения самих изображений (base64/blob), система сохраняет только минимальные метаданные.

## Компактный формат метаданных

### Старый формат (занимал много места)
```json
{"type":"blob","path":"blob:http://...","originalUrl":"blob:http://..."}
```
~100+ байт на изображение

### Новый формат (компактный)
```json
{"t":"b","o":"blob:http://..."}
```
~50 байт на изображение

**Типы изображений:**
- `t:"b"` - blob URL (временные)
- `t:"d"` - data URL/base64 (удаляется)
- `t:"u"` - external URL (сохраняется)
- `t:"p"` - pack URL (будет реализовано)

## Как это работает

### При сохранении игры
1. **Blob URL** → `{"t":"b","o":"blob:..."}` (50 байт вместо 100KB+)
2. **Data URL** → `{"t":"d"}` (7 байт вместо потенциальных мегабайт)
3. **HTTP/HTTPS URL** → сохраняются как есть
4. **Pack URL** → будут сохраняться как есть

### При загрузке игры
1. Метаданные проверяются
2. Blob URL пытаются восстановиться (могут не работать если устарели)
3. Data URL не восстанавливаются (пустые изображения)
4. Внешние URL работают как обычно

## Пример экономии места

Для 150 карт (как в вашем случае):
- **Старый способ**: 150 × 100KB = 15MB+ → `QuotaExceededError`
- **Новый способ**: 150 × 50 байт = 7.5KB → легко влезает в localStorage

## Ограничения

- ⚠️ Blob URL могут не восстановиться (временные)
- ⚠️ Data URL не восстанавливаются (изображения будут пустыми)
- ⚠️ После перезапуска браузера blob URLs исчезнут

## Рекомендации для пользователей

1. **Для больших наборов карт** используйте external URL или pack систему
2. **Для временных игр** можно загружать изображения (но они исчезнут после перезапуска)
3. **Для постоянных игр** лучше использовать паки или внешние URL
